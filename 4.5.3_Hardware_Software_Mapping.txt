4.5.3 Hardware/Software Mapping

Hardware/Software Mapping defines the allocation of software components to physical or virtual hardware nodes. The WDUPMS follows a distributed three-tier deployment architecture with clear separation between client, application server, and database server.


Node 1: Client Workstation

Hardware: Standard desktop, laptop, or mobile device with network connectivity

Software Components:
- Web Browser (Chrome, Firefox, Edge, Safari)
- Next.js Frontend Application (JavaScript/React)
- Presentation Layer: UI components, client-side routing, JWT token storage

Communication: HTTPS/REST API with JSON data format


Node 2: Application Server

Hardware: Server-grade hardware or cloud VM (8GB RAM, quad-core processor, 50GB storage)

Software Components:
- Operating System: Linux (Ubuntu 20.04+) or Windows Server 2019+
- Runtime: Node.js 18+ with Express.js 4.18.2
- Process Manager: PM2 (production)

Deployed Subsystems:
1. User Management (authentication, authorization, role management)
2. Asset Management (asset lifecycle, inventory)
3. Request Management (request processing, fulfillment)
4. Procurement Workflow (approval workflows, state machine)
5. Transfer Management (asset transfers, signatures)
6. Return Management (return processing, inspection)
7. Quality Assurance (QA inspection, condition assessment)
8. Notification & Audit (notifications, audit logging, email, scheduling)
9. Reporting & Dashboard (statistics, reports)

Supporting Services: JWT authentication, email service (Nodemailer), scheduler (node-cron), security middleware (Helmet, CORS, rate limiting)

Communication: 
- Inbound: HTTPS REST API (port 443/5000)
- Outbound: PostgreSQL (port 5432), SMTP (port 587)


Node 3: Database Server

Hardware: Dedicated database server or cloud instance (16GB RAM, quad-core processor, 100GB+ SSD)

Software Components:
- PostgreSQL 8.11.3+
- Sequelize ORM 6.35.2 (runs on Application Server)

Database Schema: 11 tables (Users, Assets, Requests, Transfers, Returns, ProcurementWorkflows, ProcurementInspections, Notifications, AuditLogs, TransferHistory) with indexes, foreign key constraints, and connection pooling

Communication: PostgreSQL protocol (port 5432) with SSL/TLS encryption

Deployment Configurations

Development: All nodes on single workstation (localhost:3000, localhost:5000, localhost:5432)

Production: Distributed deployment across university network or cloud infrastructure (AWS, Azure)

Scalability: Application server supports horizontal scaling; database server supports vertical scaling or read replicas


This mapping ensures clear separation of concerns, supports distributed deployment, and enables independent scaling of system tiers.
